# CN_OilDistiller — список проверок и ошибок

Список для последовательной диагностики серверной логики дистиллятора. Исправления вносить по одному пункту, проверяя результат перед переходом к следующему. До отдельного решения не менять другие части логики.

## 1. Синтаксическая ошибка в `Server_ExecuteCycleTick()` — исправлено, требуется проверка

Файл: `CN_MiningMachines_Server/Scripts/4_World/CN_OilDistiller_Server.c`

Исправлена некорректная конструкция `if`: теперь условие записано как `if (outputContainer.GetQuantity() <= 0)`. Установка типа жидкости выполняется только для пустой тары, а добавление продукта и списание сырья выполняются после проверки.

**Осталось проверить:** компиляцию мода и запуск цикла дистилляции на сервере. До успешной проверки пункт не считать полностью закрытым.

## 3. Поля дистиллятора не сохраняются/не загружаются корректно — исправлено в коде, требуется проверка

Файлы:
- `CN_MiningMachines_Server/Scripts/4_World/CN_MachineConfig.c`
- `CN_MiningMachines_Server/Scripts/4_World/CN_MachineConfigManager.c`

Исправлено:
- существующий JSON не перезаписывается при запуске; файл создаётся только при отсутствии;
- загрузка выполняется через `JsonFileLoader<T>.LoadFile()` с проверкой результата и понятным сообщением об ошибке;
- параметры `CN_OilDistillerConfig` проверяются до передачи конфигурации машине;
- при ошибке чтения или проверки загрузка возвращает `null`, а ошибка записывается в лог с путём к файлу и названием некорректного параметра.

**Осталось проверить:** компиляцию мода, чтение действующего JSON с пользовательскими значениями, повреждённый JSON и отдельные недопустимые значения. Файл администратора при ошибках не исправляется и не перезаписывается автоматически.

## 4. Преобразование названий жидкостей в тип жидкости

Файл: `CN_MiningMachines_Server/Scripts/4_World/CN_OilDistiller_Server.c`

Метод `GetLiquidIdFromName()` использует:

```c
return LIQUID_CRUDE_OIL.GroupToFluidType(liquidName);
```

Проверить совместимость этого вызова с API DayZ и то, что строки из JSON (`OutputClass`, `RareClass`, `WasteClass`) преобразуются в ожидаемые типы жидкости. Пока это пункт проверки, а не подтверждённая ошибка API.

## 5. Условия запуска учитывают любой из двух выходных слотов, а не фактический результат цикла

`Server_CanStartProcess()` разрешает запуск, если валиден хотя бы один слот: `RecycleOutput` или `RecycleRare`. Но обычный результат направляется в `RecycleOutput`, а редкий — в `RecycleRare`. Если основной слот непригоден, а редкий пригоден, обычный цикл может остановиться.

Согласовать проверку запуска с возможным результатом цикла и предусмотренным резервным поведением.

## 6. Проверка свободного объёма выходной тары

`IsOutputContainerValid()` проверяет наличие тары, заполненность и совместимость типа жидкости, но не проверяет, хватит ли свободного объёма на весь цикл.

Проверить граничные случаи частично заполненной тары и корректность пропорционального уменьшения расхода сырья, когда доступного места меньше объёма продукта за цикл.

## 7. Граничные случаи жидких и твёрдых отходов

Проверить сценарии:
- слот отходов пуст, контейнер заполнен или содержит несовместимую жидкость;
- твёрдый отход отсутствует, заполнен или имеет неверный класс;
- конфигурация содержит нулевые или отрицательные объёмы;
- отход невозможно создать или добавить;
- сырьё расходуется только тогда, когда соответствующий результат действительно успешно добавлен.

Это набор сценариев для проверки, а не утверждение, что каждый из них уже воспроизводится как ошибка.

## 9. Питание, остановка и повторный запуск

Проверить поведение по образцу насоса:
- питание пропало во время цикла;
- входная тара удалена или сырьё закончилось;
- выходная тара удалена, заполнена или заменена;
- процесс корректно останавливается и не продолжает списывать сырьё;
- после восстановления условий процесс может штатно запуститься снова.

Не считать реализацию насоса безошибочной — использовать её как ориентир и сравнивать фактическое поведение.

## 10. Расход энергии и валидация конфигурации

Проверить, что `EnergyUsagePerSecond` реально учитывается работающей машиной, а не только хранится в JSON.

Проверить обработку отсутствующего, повреждённого или содержащего некорректные значения JSON: безопасные значения по умолчанию, сообщения в логах и предотвращение запуска с недопустимыми параметрами.
